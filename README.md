# refcite

人文・社会科学系の学生向け、文献管理と引用文献リスト作成のツール。

文献を貯め、抜き書きと自分のコメントを残し、レポートの引用文献リストを
指定形式で出力する。データは端末内（IndexedDB）にのみ保存され、外部へ
送信されない。

## 起動

```
npm install
npm run dev      # http://localhost:3000 （開発。HMR が効く）
```

カメラ（バーコード読取）は HTTPS でしか動かない。実機で試すときは
静的書き出しを HTTPS で配信する。

```
npm start        # ビルドして https://localhost:8443 で配信
```

初回は自己署名証明書を作る。

```
mkdir -p .certs
openssl req -x509 -newkey rsa:2048 -keyout .certs/key.pem -out .certs/cert.pem \
  -days 365 -nodes -subj "/CN=localhost"
```

ブラウザの警告は「詳細 → このサイトを閲覧」で進む。スマホから試す場合は
起動時に表示される LAN アドレスへ同じ Wi-Fi からアクセスする。

移行前のバニラ版を見たいときは `npm run serve:legacy`。

## テスト

```
npm test         # 107 件
```

`test/run.mjs` が回帰テスト。`test/manual/` は出力を目視するための
スクリプトで、**合否を判定しない**ので回帰確認には使えない。

実装を変えたら、意図的に壊してテストが落ちるか（変異テスト）も確認すると
テスト自身の穴に気づける。過去にこれで 3 件の見逃しを発見した。

## 画面

| 画面 | 役割 |
|---|---|
| 書架 `/` | 文献を取り込み、プロジェクトに振り分ける |
| 文献の詳細 `/reference/?id=…` | 抜き書き（ページ必須）と所感メモを残す |
| 執筆 `/write/` | 書架から使う文献を選び、引用文献リストを出力 |

書架＝日常的に貯める場、執筆＝レポートを書く場、という時間軸の分離。

## 構成

```
src/                    ロジック（JavaScript + JSDoc）
  citation/             引用エンジン（citeproc-js ラッパ）
    styles/             apu.csl（APU マニュアル準拠・自前定義）
    locales/            CSL ロケール
  db/                   IndexedDB（Dexie）・全文検索
  import/               書誌の取得（NDL / Crossref / Open Library）
app/                    Next.js のページ（TypeScript）
components/             React コンポーネント（TypeScript）
lib/                    DB 接続・フック・カメラ（TypeScript）
public/csl/             CSL 資産。src/ から自動同期（手で編集しない）
legacy/                 移行前のバニラ版（比較用）
docs/01_architecture.md 設計書。判断の経緯と実測結果
test/run.mjs            回帰テスト
```

`src/` は Next.js から独立している。JSDoc の型注釈が TypeScript から
解決できるため、型定義を二重に持つ必要がない。テストも Node で直接動く。

## 取込の経路

| 経路 | 位置づけ | 取得元 |
|---|---|---|
| 著者名・タイトル検索 | **主** | NDL / Open Library |
| バーコード・ISBN・DOI | 副 | NDL / Open Library / Crossref |
| 手入力 | 最終手段 | — |

和書は NDL、洋書は Open Library。実測のカバー率は和書で NDL 9/10 に対し
Open Library 2/10。NDL は読み仮名を返すため 50音順ソートの前提にもなる。

## 引用スタイル

**APU ライティング・マニュアル準拠の1種のみ**を提供する。
APU 内での試験運用のため、学生が選択を誤って別形式で提出する事故を避ける。

マニュアル 5.1〜5.7 の全項目に対応し、記載例と一致することを回帰テストで
固定してある（和文・欧文とも）。

| 節 | 種別 |
|---|---|
| 5.1 | 単著（書籍） |
| 5.2 | 共著 |
| 5.3 | 編者がいる本のなかの1章 |
| 5.4 | 編書全体 |
| 5.5 | 学術雑誌論文 |
| 5.6 | ウェブサイト |
| 5.7 | 新聞記事 |

他形式が必要になったら CSL を足せばよい（エンジンは複数スタイルを扱える）。
仕様書 3.2-2 の「具体例編集による独自ルール生成」は実装したが、
試験運用の範囲外のため削除した。設計書 §4 / §9.13 に方針と実装記録がある。

## 落とし穴

実装中に踏んだもの。設計書 §9 に詳細と対処がある。

- CSL は `language` の**値**で分岐できない（存在の有無しか見ない）
- citeproc は不可視の特殊空白（U+202F）を混ぜる
- Crossref は和文論文の `title` を空にし `original-title` に実体を入れる
- NDL の責任表示は `<description>` 内の**エスケープされた文字列**
- NDL の読み仮名は著者と同数・同順で返るとは限らない（訳書）
- 漢字のコードポイント順は 50音順と一致しない
- 日本の書籍は 2 段バーコード（下段は価格コード）
